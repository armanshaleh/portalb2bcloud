## Wise Cloud Portal — Docker self-hosting

TanStack Start is full-stack: React pages, server-side rendering, server functions,
and HTTP endpoints run in one application container. Backend services remain
separate: PostgreSQL **plus Auth, Data API and private Storage**. A PostgreSQL
connection string alone will not run the current application.

### Prepare configuration

```sh
cp env.example .env.selfhost.local
chmod 600 .env.selfhost.local
```

Fill the empty values with your own self-hosted backend settings. The service-role
key is generated by that backend; Lovable Cloud's private key is not exportable.
`VITE_*` values are public and compiled into the browser files. Private keys must
only be passed at runtime. `.dockerignore` excludes local environment files;
the `.local` suffix is already ignored by Git.

### Build and run

These commands assume Bash and the simple `KEY=value` format in `env.example`.
Load the file only after filling it yourself.

```bash
set -a
source ./.env.selfhost.local
set +a

docker build \
  --build-arg VITE_SUPABASE_URL="$VITE_SUPABASE_URL" \
  --build-arg VITE_SUPABASE_PUBLISHABLE_KEY="$VITE_SUPABASE_PUBLISHABLE_KEY" \
  --build-arg VITE_SUPABASE_PROJECT_ID="$VITE_SUPABASE_PROJECT_ID" \
  -t wise-cloud-portal .

docker run -d --name wise-cloud-portal --restart unless-stopped \
  --env-file .env.selfhost.local -p 127.0.0.1:3000:3000 wise-cloud-portal

curl -I http://127.0.0.1:3000/auth
docker logs --tail 50 wise-cloud-portal
```

The image uses Node 22, runs as a non-root user, and starts
`.output/server/index.mjs`. Its build selects Nitro's `node-server` target without
changing Lovable's default deployment. Rebuild when public configuration changes;
recreate the container when runtime secrets change. If changing `PORT`, update
the container side of the port mapping too.

### Before production

- Put an HTTPS reverse proxy (Nginx/Caddy) in front of local port 3000.
- Provision your separate backend, apply SQL migrations in `drizzle/migrations/`
  in order, and migrate existing data, accounts and private files separately.
- Configure private `legal-documents` storage and its access policies; the image
  does not provision or migrate backend services.
- Set your Auth service's site URL and allowed redirects to the new HTTPS portal
  domain; keep invitation-only registration and email/password sign-in.
- Configure Auth SMTP separately. Lovable-managed email delivery and webhooks
  do not transfer automatically; they need a separate self-hosted email setup.
- Schedule a daily authenticated POST to `/api/public/cron/billing-lifecycle` with
  `Authorization: Bearer <LOVABLE_CRON_SECRET>`. Docker does not run this schedule.
- Back up database/storage and verify invitation → registration → login, billing,
  private uploads and password-reset delivery in the new environment.

The container still needs to be built and tested on a Docker-enabled host;
the editor environment has no Docker executable.
